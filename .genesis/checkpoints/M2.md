## M2 implementation plan

- Outcome: authenticated vendor owners create an organization, approved vendors manage tenant-scoped draft
  properties, policies, rooms, nearby places, and media; authorized admins review vendors and publish complete
  properties. Destinations are admin-governed and launch content remains a controlled owner decision.
- Boundary: `catalog`, ImageKit media signing/registration, provider-neutral map presentation, vendor/admin catalog
  routes and UI, indexes, docs, and M2 tests. No availability, pricing, booking, payment, finance, or public property
  page work.
- Data/security: all inputs are Zod-validated; tenant filters live in use cases/repositories; critical writes are
  transaction-coupled with audit events and idempotency keys; properties/rooms/media are archived, never hard-deleted;
  ImageKit credentials are short-lived and payload-bound to one property folder, allowed image MIME set, and size.
- Tests: catalog domain/workflow and tenant-isolation integration tests, real Mongo index/transaction evidence,
  ImageKit JWT/claim tests, route/UI smoke tests, and Playwright vendor-onboarding viewport/keyboard flow.
- Risks: cross-vendor IDOR, unauthorized publish, upload-folder escape, unverified media metadata, public fake content,
  destructive deletes, stale status transitions, and accidentally coupling the UI to MongoDB/provider SDKs.
- Rollback: remove M2-only module/routes/pages/styles/tests/wiki/checkpoint additions and additive documentation; no
  production migration, provider upload, or existing homepage redesign is authorized.
- Verification: targeted Vitest during implementation; then `npm run typecheck`, `npm run lint`, `npm run test`,
  `npm run test:integration`, and `npm run test:e2e`. `npm run build` is prohibited.

Milestone completion requires a separate verifier and explicit owner authorization.
